## Fix 1 — Mira onboarding turn

### Symptom

The very first agent message landed as an R-axis probe ("Walk me through
the last time that cost you a day you didn't expect..."). Participants
landed mid-question without orientation.

### Change

`opening_turn_message()` now produces three deterministic beats:

1. Greeting plus role-aware purpose. When the participant picked a role
   at intake the greeting addresses them in peer terms ("scientists like
   you", "facility operators like you", and so on). Empty role keeps the
   greeting neutral — the function never fabricates a role.
2. Orientation. Names the axis count (computed from
   `len(campaign.outline.axes)`, spelled in words for ≤10), the consent
   posture ("Your responses stay anonymous." vs. "Your responses can be
   attributed to you, as you chose at intake."), and the four control
   verbs verbatim.
3. Soft opener. Echoes `evidence_of_belonging` when present and asks for
   a typical day with that territory. With no evidence and no role, asks
   "what kind of work brings you in front of scientific or research
   data?" instead of guessing. Never the R-axis probe — Brain B fires
   those after the participant answers.

The first-person → second-person pivot from M11.22 still runs on the
quoted phrase so "I run cryo-EM ..." reads back as "you run cryo-EM ...".

The interviewer prompts now acknowledge the deterministic onboarding. Brain
A is told not to re-greet, not to restate controls, and on its first visible
turn to invite one more concrete moment without jumping to a hard rubric
probe. Brain B is told to set `axes_coverage` to all zeros on the first
plan and emit a `question_intent` that elaborates the participant's own
language ("Invite the participant to walk me through one recent moment
in the territory they just named"). Mandatory-close axes still must be
fired before close, but never on the first turn.

## Fix 2 — Chip-as-prefill semantics

### Symptom

Anchor chips read as directives Mira gave herself ("Move the conversation
toward integration constraints"), and tapping a chip submitted it as the
participant's full answer.

### Change

Two halves: prompt and UI.

**Prompt (Brain B chip-payload rules).** Each non-discuss chip is now a
first-person sentence starter (4-12 words, ending with an ellipsis or an
open clause that invites continuation). Few-shot examples in the prompt
make the contract concrete:

- Valid: `In our last tape-to-disk migration when…`,
  `During a metadata reconciliation that…`,
  `At the handoff between staging and analysis…`
- Invalid: `Move the conversation toward integration constraints.`
  (directive), `Tape migration friction` (label),
  `It cost us three weeks because the schema drifted.` (complete answer)

Existing chip-grounding rules and the `Discuss this more.` enforcement
in the orchestrator are unchanged.

**UI (ChatPane.svelte).**

- New `prefillChip(content)` handler used by anchor chips. Inserts the
  chip text into the composer with a leading space (when the textarea
  is non-empty and doesn't already end in whitespace) and a trailing
  space, focuses the textarea, places the cursor at the end, recomputes
  auto-resize, and pulses the same press-feedback class so the visual
  acknowledgement still fires.
- `setSelectionRange(end, end)` is wrapped in try/catch because the
  call throws on hidden inputs in some browsers; falling through is
  harmless.
- Live region announces `Inserted: <chip>. Continue typing.` so screen
  readers report the prefill.
- Each anchor chip carries `aria-label="Insert sentence starter: ..."`.
- The `Discuss this more.` chip still calls `submitChip()` which dispatches
  the submit event exactly as before. The orchestrator-side close-chip
  contract is untouched.
- Removed the hardcoded `'Tap an anchor above, or type your own answer'`
  override inside ChatPane; the textarea's placeholder now flows
  uninterrupted from the parent's bundle-aware value.
- `placeholder_with_chips` fallback in `runtime-copy.ts` updated to
  `'Tap a starter, or type your own answer.'` for the demo bundle path.
  The CITADL bundle's existing copy stays bundle-locked.

`Cmd+Enter` and `Ctrl+Enter` continue to submit (M11.23 contract).
Plain `Enter` still inserts a newline. Cmd/Ctrl+Enter on a chip-prefilled
draft submits the concatenated content.

## Fix 3 — Footer credits

### Symptom

No participant-facing study credits. CITADL needed quiet OSU/IIT/GRC
attribution and a copyright on participant routes only.

### Change

A new `BundleFooterCopy` Pydantic model under
`agentic_survey.bundles.BundleCopy.footer` with three optional string
fields: `hosted_by`, `developed_by`, `copyright`. Empty strings render
as nothing — a bundle can opt out of any one without leaking layout.

CITADL bundle gains:

```yaml
ui:
  footer:
    hosted_by: Hosted by OSU and IIT.
    developed_by: Developed by GRC.
    copyright: © 2026 CITADL.
```

Demo bundle omits the block; the Pydantic default plus the runtime
fallback (empty strings) keeps `hasFooterContent` falsy so the demo
renders no footer. That matches the brief's "or omit so the runtime
falls back" path.

`apps/web/src/routes/+layout.svelte` renders the footer only on the
participant branch (admin routes never see it) and only when at least
one of the three keys is non-empty. Markup:

```html
<footer class="participant-footer" aria-label="Study credits">
  <p class="participant-footer-credits">
    <span>Hosted by OSU and IIT.</span>
    <span>Developed by GRC.</span>
  </p>
  <p class="participant-footer-copyright">© 2026 CITADL.</p>
</footer>
```

Style is the existing editorial restraint: 10px mono uppercase wide
tracking, muted ink, one-line credit row plus an opacity-dimmed
copyright underneath, with reasonable wrap at narrow widths.

## Fix 4 — Masthead spacing

### Symptom

`<span class="hidden sm:inline">Powered by </span>Agentic Survey` could
collapse the trailing space inside the hidden span at sm+ (Svelte
template whitespace handling), producing `Powered byAgentic Survey`.

### Change

Glued a non-breaking space onto the hidden segment so the visible run
always carries explicit U+00A0:

```html
<a class="participant-attribution" href="/about"
  ><span class="hidden sm:inline">Powered by&nbsp;</span>Agentic Survey</a>
```

Built-output verification (hex dump of `_layout.svelte.js`):

```
match repr: b'Powered by\xc2\xa0</span>Agentic'
hex: 506f7765726564206279 c2a0 3c2f7370616e3e 4167656e746963
                          ^^^^ U+00A0 nbsp inside the span
```

The nbsp lands inside the span so when the span shows at sm+, the
rendered run is `Powered by Agentic Survey`. At mobile the span is
hidden and only `Agentic Survey` shows. Both `participant-wordmark`
and `participant-attribution` retain `min-h-[44px]` from M11.23.
